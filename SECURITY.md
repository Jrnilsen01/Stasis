# Security policy

## What this project is right now

Stasis is an app shell. The overlay engine is being built under `engine/` but is
not wired into the app, so the shipped attack surface is still much smaller than
the finished product's will be.

The engine's intended behaviour is documented in `docs/anti-cheat.md`, and that
document is the right thing to check a report against. If you find the engine
doing something that document says it does not do, that is a security issue
under this policy even if it harms nobody directly, because the document is a
promise users are asked to rely on.

There are no releases. The only version that gets fixes is the current `main`.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on this repository: the **Security**
tab, then **Report a vulnerability**. The report stays private between you and
the maintainer until there is a fix.

Please do not open a public issue for a security problem. This project asks
people to run a binary that reads their filesystem and will eventually draw on
top of other processes, so a disclosure with no fix available is worse here than
in most repositories.

## What to expect

One person maintains this, in the open, before any release. There is no
guaranteed response time, no bounty, and no security team. What you will get is
an honest answer about whether the issue is real and whether it is going to be
fixed.

If a report is valid and you want credit, say so and you will be credited in the
fix.

## Where to look

The Rust side is roughly 500 lines across `src-tauri/src`, and every command
exposed to the frontend is listed in `lib.rs`. The parts that touch the outside
world:

- `reveal_path` takes a path string from the frontend, creates the directory if
  it is missing, and hands it to `explorer`, `open`, or `xdg-open`. Arguments
  are passed as a single argument rather than through a shell, so there is no
  shell interpolation, but it does create directories and launch the OS handler
  on a caller-supplied path.
- `scan_steam_games` reads the Steam install path from the Windows registry and
  parses `libraryfolders.vdf` and `appmanifest_*.acf` off disk. The path can be
  overridden from Settings, so it will parse whatever it is pointed at.
- `list_modules` reads directories under the app data folder and parses a
  `module.json` from each one. Anyone who can write to that folder controls that
  input.
- `load_settings` and `save_settings` read and write a JSON file in the app
  config folder.

Nothing here opens a socket, and nothing is sent anywhere. If you find network
traffic leaving this app, that is by itself a bug worth reporting: see the
telemetry commitment in `README.md`.

## Known and not yet fixed

- `csp` is `null` in `tauri.conf.json`, so the webview runs without a content
  security policy. That is tolerable while every asset is local and bundled, and
  it has to change before any module renders third-party content in the webview.
- There is no module sandbox or permission model, because there are no modules.
  The design work for it is open in `TODO.md` section 5, and it is the decision
  that most affects this file's future.
- No release is code signed, so Windows SmartScreen will warn on any installer
  you find claiming to be this project. Treat an installer that does not warn
  with more suspicion, not less, until signing is set up.

## Out of scope

- Reports generated by a scanner with no working proof that the issue is
  reachable in this code.
- Vulnerabilities in Tauri, WebView2, or other dependencies, unless this project
  uses them in a way that makes the problem worse. Report those upstream.
- Anything that requires an attacker to already have code execution as the user.
  If they can write to the modules folder, they can write to everything else the
  user owns.

## One thing this project will not accept

Stasis is not cheat software, and reports or patches whose purpose is to make it
work as cheat software will be refused. An overlay that draws on top of a game is
close enough to that category that the line is worth stating plainly rather than
leaving to inference.
